# University Knowledge Assistant

A RAG-based Streamlit app that serves two audiences from the same indexed
document base:

- **Students** — academic knowledge assistant (courses, curricula, guides)
- **Staff / Faculty** — policy advisor (handbooks, regulations, admin policy)

Answers are generated by **Groq** (`openai/gpt-oss-120b`) grounded in
retrieved chunks, with **source citations (filename + page)** shown for
every answer.

## Architecture

```
                ┌─────────────────────────┐
                │   Offline (Colab, once)  │
                │  docs → chunks → embed   │
                │  → FAISS index + meta    │
                └────────────┬─────────────┘
                             │  commit faiss_index/ to repo
                             ▼
┌───────────────────────────────────────────────────────┐
│                     Streamlit app (this repo)           │
│                                                           │
│  user query ─▶ embed query ─▶ FAISS search (top-k)        │
│                     │ filter by role → doc_type            │
│                     ▼                                      │
│              retrieved chunks + metadata                   │
│                     ▼                                      │
│          Groq chat completion (persona system prompt)      │
│                     ▼                                      │
│            answer + cited sources shown to user             │
└───────────────────────────────────────────────────────┘
```

Only the **prebuilt FAISS index and metadata** are committed to this repo —
not the source documents. The index is produced separately by an offline
Colab notebook that chunks documents, embeds them with
`sentence-transformers/all-mpnet-base-v2`, and writes:

- `faiss_index/index.faiss` — vector index (`IndexFlatIP`, cosine similarity)
- `faiss_index/metadata.json` — one entry per chunk: `id`, `source_file`,
  `page`, `doc_type` (`academic`/`policy`), `text`, `ingested_at`
- `faiss_index/manifest.json` — content hashes, used for incremental re-indexing

**The embedding model in `src/config.py` must exactly match the model used
to build the index.** If you change one, rebuild the other.

## Project structure

```
university-rag-assistant/
├── app.py                  # Streamlit UI + chat loop
├── requirements.txt
├── faiss_index/             # prebuilt index + metadata (from Colab)
└── src/
    ├── config.py            # paths, model names, role → doc_type mapping
    ├── retriever.py         # FAISS search + doc_type filtering
    └── llm.py               # Groq client, persona prompts, citation building
```

## Setup

1. Copy the `faiss_index/` folder produced by the indexing notebook into
   the repo root (same level as `app.py`).
2. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```
3. Set your Groq API key as an environment variable — **never hardcode it**:
   ```bash
   export GROQ_API_KEY="your-key-here"
   ```
4. Run locally:
   ```bash
   streamlit run app.py
   ```

## Deploying to Streamlit Cloud

1. Push this repo to GitHub, including the `faiss_index/` folder.
   - If the index exceeds GitHub's file size limits, use
     [Git LFS](https://git-lfs.com/) for the files under `faiss_index/`.
2. On [share.streamlit.io](https://share.streamlit.io), create a new app
   pointed at this repo and `app.py`.
3. In the app's **Settings → Secrets**, add:
   ```toml
   GROQ_API_KEY = "your-key-here"
   ```

## Updating the index

Documents change over time. Re-run the offline Colab indexing notebook —
it only re-embeds new or changed files (via the manifest hash check) — then
replace the `faiss_index/` folder in this repo and redeploy.

## Notes on retrieval

- Retrieval is currently **semantic-only** (dense embeddings via FAISS).
  A hybrid semantic + keyword (BM25) retrieval layer can be added later for
  queries that hinge on exact terms (clause numbers, form names, acronyms).
- `doc_type` filtering means Students only retrieve `academic`-tagged
  chunks, while Staff/Faculty retrieve both `academic` and `policy` chunks.
  Adjust `ROLE_DOC_TYPES` in `src/config.py` to change this.
